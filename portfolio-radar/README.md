# Портфель Романова — первая версия

Telegram-бот принимает скриншоты криптовалют, акций и облигаций, сохраняет подтверждённые остатки и готовит персональные обзоры. Пользователь может вести до пяти счетов, обновлять весь счёт или только показанные позиции, выбирать время обзора и удалять свои данные.

## Состояние

Сервис активирован: https://t.me/portfolius_bot. Серверная часть и база работают в существующем Supabase-проекте Telegram Strategy bot. Ключи Telegram и OpenAI подключены через Vault; значения не входят в код. Webhook и меню команд зарегистрированы. Живое распознавание синтетического скриншота проверено на BTC 0.125, ETH 2.5 и MSFT 12; реальный вызов web search также выполнен. Проверен реальный брокерский скриншот: все 9 видимых строк прошли в предпросмотр, включая отдельные строки одного эмитента; доставка предпросмотра в Telegram подтверждена. У 3 инструментов установлено точное соответствие в справочнике, у 6 требуется уточнение. Средние цены покупки не подменяются текущими. Подтверждение пользовательского портфеля остаётся за пользователем.

Health: https://swlwrhkfcmsexscfsrtc.supabase.co/functions/v1/portfolio-radar/health

## Что работает в коде

- Приём фотографий и изображений-файлов в приватном чате, несколько скриншотов в одной загрузке; `/done` завершает загрузку.
- Модель `gpt-5.4-mini-2026-03-17`, строгая JSON-схема извлечения, `store:false`. Скрытые поля не додумываются. Лоты и проценты номинала не подменяются количеством и денежной ценой. Средняя цена покупки извлекается только при явной подписи; текущая цена под названием актива ею не считается.
- Идентификация криптоактивов через CoinGecko, бумаг Московской биржи через ISS, американских акций через каталог SEC. Поиск учитывает полные названия и бумаги с приостановленными торгами. Неоднозначные строки сохраняются только по отдельной кнопке «Сохранить все позиции с пометками»; точные котировки и персональные новости для них отключены до уточнения. `/edit` позволяет выбрать строку кнопкой. Обычный текст, например «5 — TE.PA, 2 штуки», и `/fix 5 TE.PA` уточняют инструмент до или после сохранения. Если количество не указано, оно сохраняется; изменения проходят через предпросмотр.
- Точные десятичные количества как строки. Совпадающие строки перекрывающихся скриншотов не складываются. Строки с одинаковым названием и разным количеством остаются отдельными неподтверждёнными инструментами; бот не суммирует их и не отклоняет всю загрузку. Балансы заменяются, не трактуются как сделки.
- Подтверждение, частичное обновление, полная замена конкретного счёта; атомарный commit в PostgreSQL, проверка владельца и версии, идемпотентное повторное подтверждение.
- История снимков, команды счёта, времени, паузы, возобновления, удаления.
- Котировки CoinGecko и MOEX; для иностранных акций добавлен справочный источник Yahoo Finance по основному рынку, с проверкой названия, валюты и времени цены; Finnhub API key остаётся необязательным резервом. Если котировки недоступны, это видно в обзоре.
- Поиск новостей через OpenAI web search с источниками и датами. Источники сверяются с URLs фактической поисковой выдачи, старые и будущие публикации отсекаются. По акциям и общему рынку в выходные окно начинается с пятницы, чтобы включить последнюю торговую сессию; период и даты явно указаны. Криптоактивы сохраняют окно 24 часа. Это проверка происхождения и времени, не гарантия истинности каждого утверждения; требуется редакционный контроль на пилоте.
- Дедупликация новостей, отдельное обозначение отсутствия событий и проблем получения данных, ближайшие события со ссылками.
- Общий кэш анализа каждого инструмента, очередь заданий с повторными попытками, расписание с часовым поясом.
- Очередь исходящих сообщений. При неизвестном результате сетевой отправки статус `uncertain`: автоматический повтор отключён, потому что Telegram sendMessage не имеет ключа идемпотентности. Для таких случаев нужен операционный разбор, гарантия exactly-once не заявляется.

Живой health отвечает 200. Неподписанные webhook и worker-запросы возвращают 401. Планировщик исполняет задания. Получение реальных котировок проверено на BTC, SBER и ОФЗ 26238. Все тестовые пользователи и данные интеграционного теста откатываются.

## Подключение

1. Создать нового бота через @BotFather. Не переиспользовать токен бота с работающим webhook.
2. Добавить в Supabase Vault секреты `portfolio_telegram_token` и `portfolio_openai_key`. Для существующего секрета использовать `vault.update_secret` с его ID; не создавать дубли имён. Ключи не входят в репозиторий.
3. Вызвать `POST /functions/v1/portfolio-radar/register` с заголовком `x-portfolio-worker-secret`, значение которого хранится в Vault как `portfolio_worker_secret`. Можно вызвать через pg_net, получая ключ внутри SQL, не выводя его. `/register` проверяет getMe, отклоняет бота с чужим webhook, затем ставит webhook и меню команд.
4. Начать диалог с ботом, загрузить реальный тестовый скриншот, подтвердить позиции, проверить ежедневную сводку по расписанию, новое количество, частичное обновление и `/delete`.

Секреты webhook и worker создаются случайно миграцией. Worker вызывает их через закрытый RPC. Публичные и authenticated-роли не имеют доступа к таблицам, настройкам и RPC портфеля; запросы пользователей обслуживает только бот после проверки Telegram webhook secret и совпадения отправителя с приватным чатом.

Вместо Vault AI-ключ можно задать как секрет среды `PORTFOLIO_OPENAI_KEY`. Telegram token должен быть в Vault для запуска cron-диспетчера: он намеренно не активирует фоновые вызовы до его подключения. Ключ Finnhub (`portfolio_finnhub_key`) и Demo API key CoinGecko (`portfolio_coingecko_key`) необязательны.

## Развёртывание

Код не требует npm-зависимостей: стандартные Fetch API, Web Crypto и PostgreSQL REST/RPC. Edge entrypoint — `src/index.ts`, вместе с `src/*.js` и `deno.json`. При повторном deploy через connector явно передавать `import_map_path: deno.json`, чтобы не наследовался абсолютный путь предыдущей сборки. URL регистрации webhook строится из SUPABASE_URL, а не внутреннего req.url Edge Runtime. `verify_jwt=false` нужен для Telegram; вместо JWT внутри проверяются раздельные случайные секреты webhook и worker.

SQL применён именованными удалёнными миграциями: `portfolio_radar_core`, `portfolio_radar_scheduler`, `portfolio_radar_recognition_fix`, `portfolio_radar_corrections_and_feeds`, `portfolio_radar_research_fairness`, `portfolio_radar_daily_news_and_subscriptions`, `portfolio_radar_scheduled_only`, `portfolio_radar_rub_weekly_freemium`. Файлы с именами исправлений предназначены для обновления прежних версий; schema.sql содержит базовый контур, а subscriptions.sql добавляет подписки и обновляет расписание/очистку. При новой установке subscriptions.sql применяется после schema.sql, затем scheduled_only.sql. Повторно запускать schema.sql поверх существующих таблиц нельзя. Для изменений создавать следующую миграцию. SQL cron содержит адрес выбранного проекта и при переносе должен быть изменён.

Cron `portfolio-radar-worker` проверяет готовую работу каждые 15 секунд и не делает внешних HTTP-вызовов без токена или при занятом worker. `portfolio-radar-cleanup` очищает временные данные каждый час. Обработка сообщений и получение новостей используют независимые блокировки по 150 секунд; отправка сообщений имеет атомарный захват. Поиск новостей запускается в OpenAI background mode, ID сохраняется в очереди и опрашивается до 8 минут без повторного создания запроса. В этот поиск передаются только публичные данные инструментов, без количеств и личных сообщений. `store:true` нужен для надёжного получения результата; после записи результата в кэш выполняется DELETE response. Снимки и текстовые уточнения по-прежнему используют `store:false`. См. [OpenAI Background mode](https://developers.openai.com/api/docs/guides/background).

 извлечение текста и проверка инструментов разбиты на этапы. Позднее масштабирование требует замеров реальной длительности, стоимости и загрузки очереди.

## Границы первой версии

- Поддержка интерфейсов брокеров не объявляется универсальной до теста реальных скриншотов. Неизвестные активы остаются видимыми для исправления; фьючерсы, шорты и опционы не рассчитываются как спотовые остатки.
- Состав актуален на дату последнего подтверждения. История сделок, пополнений и выводов не восстанавливается по скриншотам. Полная доходность, точная стоимость облигационного портфеля с НКД и вклад позиций пока не рассчитываются.
- Свежесть новостей ограничена доступностью источников и общим дневным выпуском по времени Москвы. В день без событий не генерируется искусственное наполнение.
- Групповые чаты, торговля и привязка к оплате клуба не входят в этот выпуск. Рублёвые подписки Т‑Банка и реферальный учёт реализованы; настройки запуска описаны ниже.
- До 8 изображений, 8 МБ каждое и 16 МБ на загрузку, 100 позиций на счёт, 5 счетов, 6 загрузок за скользящие сутки. Котировки и новости приходят только в ежедневной сводке; ручных обзоров нет.
- Скриншоты загружаются из Telegram для анализа и не сохраняются отдельными файлами. Ссылки file_id удаляются после подтверждения либо в течение суток. Обработанные raw updates очищаются сразу; завершённые задания и журнал отправки — через 7 дней; необработанные платёжные события сохраняются для сверки. `/delete` отключает продление и удаляет портфели и историю из рабочей базы; минимальные записи оплат/рефералов остаются для расчётов; политика резервных копий определяется Supabase.

## Исправление распознавания

Устранена ошибка чтения пустого успешного ответа PostgREST (`201` с `return=minimal`). Раньше запись сообщения или кэша успевала сохраниться, затем обработчик падал на JSON.parse. Это приводило к ложным ошибкам, дублям уведомлений и неопределённым инструментам. Отдельные строки одного эмитента теперь проходят в предпросмотр без принудительного объединения.

## Ограничения справочных цен

Yahoo Finance — дополнительный публичный источник без гарантии доступности API. Число показывается только при совпадении инструмента и свежем timestamp, вместе с биржей и ссылкой. Это справочная цена на другом рынке, а не обещание продажи заблокированной бумаги у российского брокера. При недоступном источнике цена не восстанавливается из новостей или языковой модели.

## Общие дневные новости

`src/daily.js`: ключ `research:daily:v1:YYYY-MM-DD:<ISIN или provider ID>`, без user_id. День меняется в 00:00 Europe/Moscow. При первом запросе формируется выпуск для актива; ежедневные сводки других пользователей читают тот же результат. Общерыночный выпуск также один на всех. Одинаковый ISIN объединяет листинги; без ISIN используется подтверждённый ключ провайдера. Разные одноимённые криптотокены не объединяются.

Уникальный `pr_jobs.job_key` не допускает двух заданий одного выпуска. Перед POST в OpenAI сохраняется намерение, затем response_id. Опрос продолжает тот же response; при неопределённом исходе отправки повторный платный POST в этот день запрещён. Это может дать явный пропуск данных до следующего дня при аварии, зато не создаёт скрытых повторных расходов. Ошибка источника не равна отсутствию новостей. Запрошенный лимит инструментов — 4, но это не денежный лимит: в одном замере API вернул 5 записей web_search_call. Контроль расходов опирается на фактическую usage и число вызовов.

Дневные результаты хранятся 7 суток. Дата и время окна проверки показаны в сводке. Новости после проверки переходят в следующий выпуск; немедленные новостные оповещения в эту схему не входят. Котировки имеют отдельный общий кеш на 15 минут, с сохранением биржевого timestamp. Сборка персональной сводки выполняется кодом, без дополнительного вызова модели.

Тест 100 портфелей с одинаковым инструментом создаёт 2 анализа: инструмент и рынок. Это функциональная проверка дедупликации, не нагрузочный тест всей системы. Перед массовым запуском нужно измерить время обработки сотен уникальных активов: текущая фоновая очередь ограничивает скорость старта исследований.

## Подписки и рефералы

**Статус 2026-09-13:** фримиум включён, версия 0.3.0. Шлюз Radar подтверждает наличие боевых RUB-настроек. Прямой Init для CC-подписки дважды и диагностический обычный Init возвращают `Success=false`, `ErrorCode=9999`, «Повторите попытку позже». Поэтому `tbank_enabled=false`: ссылка оплаты пользователю не предлагается. COF на терминале ещё не подтверждён реальной оплатой. Для открытия продаж нужен успешный Init и проверка банковского подключения; после этого включается готовый сценарий подписки. Реальных списаний не было.

Новые оплаты — **290 ₽ каждые 7 дней через Т‑Банк**. Используется терминал действующего Yield Radar: `https://yield-radar-bo7y.vercel.app/api/portfolio-billing`. В Radar добавлен изолированный шлюз из каталога `gateway/`; обычные платежи Radar не изменены. Банковские `TBANK_TERMINAL_KEY` и `TBANK_PASSWORD` остаются на его сервере. Portfolius подписывает запросы Ed25519; закрытый ключ и URL шлюза хранятся в Vault, публичный ключ — в `gateway/src/portfolio-public-key.mjs`.

Первые 72 часа после первого подтверждённого портфеля — полный доступ. Затем бесплатно доступны новости, котировки и календарь **первых трёх уникальных определённых активов**, в том же порядке счетов и строк, что `/portfolio`. Выбора бесплатных активов нет. Остальные позиции сохраняются; полный обзор доступен по подписке. Первые три ключа фиксируются перед началом дневного выпуска. Проверка доступа выполняется до поиска/котировок и повторно перед сборкой ответа. Обновление скриншотов и исправление позиций сохраняются. Удаление портфеля не сбрасывает пробный срок или дневную квоту.

`/subscribe` показывает цену, период, дату доступа и согласие на автосписания. Первая неделя оплачивается сразу после явного согласия; остаток пробного срока добавляется к доступу. Банк сохраняет карту через родительскую CC-операцию (`Recurrent=Y`, `DATA.OperationInitiatorType=1`); последующие MIT COF операции (`R`) создаются через Init + Charge. `RebillId` хранится в закрытой схеме, номера карт не сохраняются. `/unsubscribe` отключает будущие списания и сохраняет оплаченный период; `/delete` тоже отключает продление. `/pause` останавливает только рассылку.

`database/tbank.sql` применяется после прежних миграций, перед `database/freemium.sql`, затем `database/tbank_hardening.sql`. Шлюз ограничен заказами `pr_…`, суммой 29000 копеек, собственным NotificationURL и банковским HTTPS. Подтверждение `AUTHORIZED` сохраняет банковскую привязку, но не даёт платного доступа. Только `CONFIRMED` атомарно выдаёт 168 часов доступа, начисляет рефералу 20% и ставит уведомление в очередь. Повторное подтверждение не продлевает срок. Возврат уменьшает комиссию и отключает продление; позднее подтверждение не отменяет возврат.

Cron `portfolio-radar-billing` проверяет задолжавшие продления каждую минуту независимо от очереди новостей. Перед Init/Charge атомарно сохраняется факт начала запроса. Сбой после Charge приводит к GetState, повторный Charge автоматически не отправляется. Неопределённые платежи требуют сверки, а не повторного списания. Неподписанный callback отклоняется; ответ банку `OK` появляется только после сохранения результата. Продажи регулируются `pr_billing_settings.tbank_enabled`; цена фиксирована в рублях. Старый Stars-контур не используется для новых счетов (`enabled=false`, `price_stars=null`).

Реферал: первый пригласивший закрепляется при первом запуске. С каждой подтверждённой недели — 20%, то есть 58 ₽ при полной оплате. Кабинет `/referral` показывает удержание, доступную сумму и проведённые выплаты в рублях. Удержание минимум 21 день; автоматических переводов партнёрам нет. `pr_rub_record_payout` фиксирует фактически выполненный перевод в копейках и не допускает повторного учёта. Возвраты уменьшают начисления, в том числе корректируют ранее выплаченные суммы.

Кнопка «Открыть весь портфель» есть при старте, сохранении, просмотре портфеля и в ежедневной сводке бесплатного пользователя. Платным пользователям предложение не показывается.

## Сводки только по расписанию

Команда `/brief` удалена из меню, подсказок и условий подписки. Старые сообщения с этой командой получают объяснение расписания. Обычные просьбы обновить новости/котировки отвечаются локально; если такую просьбу распознал разборщик исправлений, он также не запускает обзор. Обновление состава скриншотами и подтверждённые исправления остаются доступными.

`handleDigest` допускает только задания планировщика с `daily=true` и ключом владельца. Ручные и старые recovery-задания отклоняются до запросов к источникам. RPC `pr_enqueue` больше не принимает задания digest: их создаёт только `pr_daily_jobs`.

`pr_digest_days` атомарно резервирует один выпуск на пользователя за календарный день Europe/Moscow. Смена часового пояса, пауза/возобновление и удаление/повторное создание портфеля не сбрасывают лимит. Служебная отметка дня хранится 30 дней отдельно от позиций и истории. Подписки и пользовательское время рассылки продолжают работать; завершённый дневной выпуск повторно не запускается.
